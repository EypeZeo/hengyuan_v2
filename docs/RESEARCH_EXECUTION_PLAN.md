# HengYuan v2 研究与自动执行规划（v2.11.0）

版本：v2.11.0
日期：2026-11-15
用途：整合五份研究报告，规定当前研究、执行与分阶段实施的任务要求。
适用范围：个人使用的 Binance 现货自动交易，预期持仓数小时至数周；本地研究与回测，东京 VPS 执行。
状态：正式规划；尚未实现的功能、研究参数和运行验证按各节标记。站点状态与生产前置条件以主路书第 1.5 节为准。

## 1. 总体方向

项目近期目标是完成一个可以回答以下问题的最小系统：在约 1,000 CNY 初始资金、每月追加 200 或 500 CNY 的条件下，一套简单现货策略能否在计入交易费用、汇率和运行费用后，取得值得承担相应回撤的增值；通过验证后，能否在受限授权内可靠地自动运行。

新版规划采用两项并行工作：

1. **研究与资金核算**：数据可用时间、实验登记、三个账本、简单策略、统计检验、前瞻观察。
2. **执行与运行安全**：现有订单流程验证、最小成交账务、硬件范围批准、故障恢复、通知和目标主机测试。

两项工作共同满足完成条件后，才进入小额真实资金自动交易。USD-M、双腿套利、做市、毫秒级订单流研究和远程写入管理界面，安排在现货首轮结果之后。

主要规划决定如下。

| 决定 | 对后续工作的影响 |
| --- | --- |
| 优先建立 CNY 核算与现实成本模拟 | 先判断策略是否有经济价值，再增加策略数量或服务器开支 |
| D1 立即开始，拆成数据时间信息、实验登记和统计验证 | 研究不再等待衍生品开发或双腿套利毕业 |
| 现货趋势策略先行，顺势回调作为第二个候选 | 先控制搜索规模，再研究更复杂的市场状态和仓位调整 |
| 账户、订单、存储和授权的安全条件始终生效 | 可选市场过滤器通过实验决定是否启用 |
| 保留现有同步持久化流程，先测量目标主机表现 | 异步 WAL 作为有条件的性能改进，不作为首轮研究前提 |
| 硬件范围批准属于自动交易的前置功能 | 与远程管理界面分开开发；范围批准完成前保留逐单确认 |
| 实盘费用按实际账户和主机报价核算 | 100 USD/月是预算上限，不是采购目标 |
| 新策略、新参数和扩大授权均有独立版本 | 自动调整只在已经验证和批准的规则范围内进行 |

本规划的优先级是 P0 完成条件、P1 后续改进、P2 研究储备。P0 不表示所有任务同时开始；依赖顺序见第 12 节。

## 3. 经济检验与三个账本

### 3.1 交易资产账

按资产记录可用数量、冻结数量、待结算数量、成交、手续费资产和余量。买入、卖出、取消、部分成交及手续费补报均有独立事件；每个事件可重复输入，账务结果保持一致。

模拟与实盘采用同样的事件字段。模拟交易所负责生成成交事件，实盘适配器负责转换交易所回报，账务投影共享相同的数量与费用规则。研究账本可以先完成；实盘 E0 的完成条件仍包括权威成交事件持久化和恢复验证。

最小模拟器必须处理：

- 数量步长、价格步长、最小金额、手续费币种和收费时点。
- 买入手续费从基础资产扣除后，可卖数量相应减少。
- 部分成交、拒单、取消延迟、最小可卖数量不足及剩余小额资产。
- 订单和在途订单共同占用余额与风险预算。
- 已扣入成交价格的价差或冲击不再重复计入成本。

例如，价格 100、买入金额 100、每边手续费 10 bp，买入手续费从基础资产扣除，卖出手续费从报价资产扣除；忽略步长与价格变化，最终所得为 99.8001。该例用于检验记账程序，10 bp 不代表用户账户的实际费率。

### 3.2 资金流调整绩效账

以单位净值计算策略收益和最大回撤。充值按充值前净值增加份额，提款按提款前净值减少份额；资金进出本身不产生投资收益。

设资金流发生前市值为 V，份额为 U，单位净值为 N=V/U。充值 D 后：

\[
U_{\mathrm{new}}=U+D/N,\qquad V_{\mathrm{new}}=V+D.
\]

净值仍为 N。净值回撤为：

\[
DD_t=1-\frac{N_t}{\max_{s\leq t}N_s}.
\]

交易账户内承担的费用影响该账户净值。账户外费用通过 CNY 综合账评价；如另外展示全费用单位净值，使用明确标记的虚拟费用分录，并保持实际资产账不重复扣费。充值不重置历史高点、已触发的风险暂停或人工复核要求。份额为零、全部提款和重新投入须有单独生命周期规则。

校验例：初始 1,000 CNY、1,000 份，市值下降到 900 后充值 500，净值仍为 0.9；随后资产上涨 10%，市值为 1,540，单位净值 0.99，回撤为 1%，累计投入 1,500，投资盈亏为 40。

### 3.3 所有者 CNY 综合账

同时展示投资收益和包含外部支出的综合结果：

\[
P_{\mathrm{investment}}=V_{\mathrm{CNY}}+W-C,
\]
\[
P_{\mathrm{allin}}=V_{\mathrm{CNY}}+W-C-K_{\mathrm{outside}}.
\]

C 是累计投入交易账户的 CNY 金额；W 是累计提取并折算成 CNY 的金额；K_outside 是由账户外支付、尚未计入 V 的项目费用。账户内已经扣除的费用不再计入 K_outside。

V 包括所有交易资产和闲置资产，按各自可用估值与汇率换算。对历史充值提款，采用实际兑换成交；只做模拟时，分别登记兑换成本和参考汇率的来源。

同时报告：

- 全部项目费用后的 CNY 盈亏。
- 仅增加本策略所需费用后的增量盈亏。
- 剔除充值提款的单位净值、最大回撤和未恢复时长。
- 实际资金流的资金加权收益率；现金流不支持唯一解时明确显示不可计算。
- 数字资产价格、稳定币兑换价值、USD/CNY 汇率、交易费用与运行费用的贡献。交互项采用固定分解顺序或另列，不声称存在唯一分解。

USDT/USD 和 USD/CNY 分别建模。USDC/USDT 只能提供相对价格信息；缺少独立美元估值时，不据此认定其中某个币已经偏离美元。

### 3.4 成本上限与停止条件

每月固定费用 F（USD）、汇率 X（CNY/USD）、资金 V（CNY）对应费用比例：

\[
c_{\mathrm{fixed}}=\frac{FX}{V}.
\]

仅作算术示例：X=7、V=1,000 时，10 USD/月对应 7% 的初始资金，100 USD/月对应 70%。这里未引用当前汇率或服务器报价。本金增加后应逐月重算，不能将追加资金计为策略收入。

第一轮必须同时比较不交易的 CNY 资金、不交易的报价资产、相同资金投入日期的买入持有，以及候选策略。持有资产的对照也计交易费用、兑换费用与自身需要的运行费用；只有自动策略需要的 VPS 成本不能强加给所有对照以抵消差距。

若包含必要运行费用后优势不足，输出可执行结论：继续本地研究、延后常驻部署、降低运行费用或等待资金规模变化。暂不交易是允许的结果，不以扩大风险预算补偿固定费用。

## 4. 数据与实验登记先行

### 4.1 最小数据范围

首轮研究可从 BTCUSDT、ETHUSDT 的现货 OHLCV 开始，先验证可用覆盖与规则变化。两个标的是候选范围，具体选择也进入实验登记。先用 1h/4h/1d 数据筛选；需要细化成交模拟时，只为进入下一阶段的候选补充相应时期的更细数据。

已有 D0 录制任务继续按既定权限与资源限制维护。L2 扩容、更多交易所和高价数据源，按候选策略的实际需求安排。

| 数据 | 最小用途与规则 |
| --- | --- |
| OHLCV | 确认周期结束、缺口、重复、时区和修订；未结束周期不能当作完整周期 |
| 交易规则 | 保存生效时间、获取时间和版本；历史规则缺失时做明确的情景分析 |
| 费率与收费资产 | 区分账户实测、公开费率和研究假设 |
| 汇率与稳定币兑换价格 | 保留来源、时间和是否为实际可兑换价格 |
| 前瞻行情 | 保存实际接收时间和缺口；用于检验历史数据中的延迟假设 |
| 账户与订单 | 仅在相应授权下读取；账户信息与公开行情使用独立权限 |

历史数据来源可优先调查交易所官方历史文件与市场数据接口。每个来源需记录覆盖时间、缺失情况、修订方式、使用条件及费用；本规划不将某个未核实的数据套餐列为前置采购。

### 4.2 逐时点可用性

数据记录至少表达 event_time、available_at、received_at、revision_id、source_id 和时间信息质量。历史回填不能补造真实接收时间；采用 modeled_available_at 时必须保留估计方式和延迟压力情景。

决策只能读取 available_at 不晚于 decision_time 的记录；依赖实际接收路径时还需满足 received_at 不晚于 decision_time。当前周期收盘在确实收到后可以参与决策，模拟成交必须发生在此后可实现的时间和价格。窗口、标准化与参数训练的结束时间也必须满足这一规则。

逐步执行测试覆盖未来值、全样本标准化、修订数据、跨标的时间错位、预计算信号和缺口。当前 SAFE-05 保留为已有检查，并增加完整逐步对照与可解释的拒绝原因。

### 4.3 实验登记与保留数据

每次研究保存 trial_id、family_id、父实验、研究目的、候选参数列表、数据版本及范围、代码版本标识、成本模型、训练与评价窗口、随机种子、失败原因、观察结果的时间和参与选择的人员或程序。

完整登记包括失败候选与无交易候选。诊断实验若影响了后续规则、参数或策略选择，纳入选择历史。报告总尝试数、候选间相关性和试验族；不能只保留获胜参数。

按时间建立开发、滚动样本外、最终保留和未来观察数据。保留数据只有在访问记录支持未用于研究时，才承担独立检验作用。已经看过的历史时期可用于复核；新的前瞻观察负责补充独立信息。修改策略后创建新实验，不沿用旧版本的最终评价结论。

数据版本目录、只读访问、追加式登记、权限和访问记录共同管理研究资料。登记保存已有版本标识、文件清单、行数和时间覆盖；本轮规划不要求生成内容摘要文件。

| STR-BREAKOUT-01 | 区间突破与退出规则 | 趋势族的替代形式，先作储备 |

所有候选从现货只做多开始。BTC 与 ETH 的收益具有共同市场影响，分别测试和组合测试须保留这种依赖关系。

第一批按以下有限范围准备实验，具体参数在运行前登记并固定：

- STR-TREND-01：4h 决策，14 日或 28 日价格变化为方向信号；大于零时允许进入，不大于零时退出；最长持有 21 日。达到时间上限后，即使趋势仍为正，也需先看到进入条件解除，再允许下一次进入。
- STR-PULLBACK-01：先固定 4h 决策、14 日趋势和过去 7 日的价格标准化窗口；趋势参考截至上一周期，均值与标准差也排除当前值；进入阈值只比较 z≤−1.5、z≤−2 两个候选。回到均值、趋势失效或持有 72 小时，任一满足即生成退出意图。平仓后须经历预先定义的复位条件才允许再次进入。
- 先固定一种研究配置比例，例如投入时可用权益的 50%；25% 和 75% 留作登记后的敏感性实验。上述比例没有实盘授权效力。
- 时间周期迁移、更多阈值、额外止损和突破策略均使用新实验编号。第一批不将全部维度组合成大型参数搜索。

每个候选都写明决策时刻、下单时刻、价格来源、部分成交处理、持有计时起点、退出优先级和复位条件。只有当前信号改变且对应交易可以执行时才产生订单，不能每根周期重复买入。

研究中的持有上限表示到时发出受约束的退出意图。行情不可用、交易所停机或订单结果未知时，记录超时暴露并执行恢复规则；不把计划退出时间当作实际成交保证。

### 5.2 仓位模式分开表达

现有 risk_fraction 继续保留其当前含义。新增仓位模式需显式选择 fixed_allocation 或 volatility_target；按止损距离推导数量的模式另列，不能复用同一个数值解释三种含义。

第一轮先使用固定配置比例。波动率模式只有在简单策略完成研究后增加：

\[
\widehat{\sigma}_{a}=\max\left(
\sqrt{B}\widehat{\sigma}_{fast},
\sqrt{B}\widehat{\sigma}_{slow},
\sigma_{floor,a}\right),
\]
\[
w_{vol}=\min\left(w_{max},\frac{\sigma_{target,a}}{\widehat{\sigma}_{a}}\right).
\]

B 是每年的观测周期数；两个估计量以每周期收益为单位，floor 和 target 以年度波动率为单位。这里的年化是明确的尺度规则；估计量、极低波动率、缺口和异常值的处理须在开发数据中固定。

最终目标权重按多个上限取最小值：

\[
w_{target}=\min(w_{strategy},w_{vol},w_{market},w_{account},w_{scope}).
\]

未启用的可选上限取不构成额外限制的值。运行安全条件不满足时，新增风险权限为零。不得在不同层重复乘同一个降仓系数。

实际数量由权益、价格、现有持仓、待成交订单、收费资产和交易规则共同计算；整数数量按允许步长向安全方向处理。资金不足或最小订单无法满足时返回 INFEASIBLE_CAPITAL，并保留闲置资产。

常规再平衡可以设置时间间隔、最小变动幅度和成本预算。硬性风险限制、授权收紧和已确认的退出条件不受常规再平衡等待时间约束。

### 5.3 加仓、减仓与退出的统一优先级

1. 核实数据、账户、授权、存储和订单状态是否允许该动作。
2. 处理待成交订单及其最坏情况下的风险，避免取消尚未确认就重建仓位。
3. 执行硬性风险限制与到期退出。
4. 执行策略退出、减仓和常规再平衡。
5. 最后处理进入或加仓。

加仓只允许在预先验证的规则下向目标数量调整，并同时满足范围和账户限制。下跌后的额外投入不自动形成补仓指令。定期追加资金先进入现金账，后续仍由相同交易规则决定用途。

首轮不要求实现分数 Kelly。均值与尾部损失估计尚不稳定时，先使用明确的配置比例和额度上限；Kelly 保留为后续独立研究课题。

## 6. 统计评价与选择控制

### 6.1 先定义要证明的结果

首轮主要经济评价为包含必要费用的 CNY 综合结果；策略机制评价同时使用资金流调整后的收益。所有对照采用相同的资金投入日历、数据时间范围和可用信息。预注册时明确净优势相对于哪项参照方案、采用何种收益尺度和评价期限；CNY 期末金额差、日收益均值差与 Sharpe 差分别报告。

对市场过滤器，预先选择以下一种目标：

- 收益改进：扣费收益改善，风险没有超过预设容忍范围。
- 防御改进：回撤、尾部损失或恢复时间改善，收益损失不超过预先批准的容忍范围。

容忍范围不能看到结果后再选择。单位净值、CNY 盈亏、费用和实际暴露分别报告；不把低暴露带来的回撤下降直接归为状态识别能力。

### 6.2 滚动验证与数据分离

训练、参数选择和测试严格按时间推进。每个测试段只使用之前可获得的信息；模型、阈值、波动率估计方式和成本模型均在进入该段前固定。

净化依据真实信息区间：标签跨越的未来时间、用于评价交易结果的持有区间，以及跨段未结算状态。不能使用平均持仓时长替代最长相关区间。

特征读取测试期之前的历史数据属于正常预测条件。净化和禁区应针对信息泄露与评价依赖分别设计，不能一概删除所有可用历史。对于 CPCV 中位于测试段之后的训练样本，需处理其特征记忆与测试段重叠；指数加权统计还需定义初始化、截断误差或独立状态重建。

walk-forward 是主时间顺序。CPCV/PBO 用于诊断选择不稳定性；其组合路径不作为真实可部署时间顺序。

### 6.3 HAC 对 Sharpe 的使用

对频率一致的完整净收益序列 x_t，包含空仓期，先明确其是否扣除了参照资产收益。设：

\[
\widehat{\mu}=\frac{1}{n}\sum x_t,\quad
\widehat{\sigma}^2=\frac{1}{n}\sum(x_t-\widehat{\mu})^2,\quad
\widehat{s}=\widehat{\mu}/\widehat{\sigma}.
\]

使用插入估计的影响函数：

\[
\widehat{\psi}_t=
\frac{x_t-\widehat{\mu}}{\widehat{\sigma}}
-\frac{\widehat{s}}{2}
\left(\frac{(x_t-\widehat{\mu})^2}{\widehat{\sigma}^2}-1\right).
\]

在相应平稳性、矩条件和弱依赖条件下，以 Bartlett 权重估计长期方差：

\[
\widehat{\gamma}_k=
\frac{1}{n}\sum_{t=k+1}^{n}
(\widehat{\psi}_t-\bar{\psi})(\widehat{\psi}_{t-k}-\bar{\psi}),
\]
\[
\widehat{\Omega}=
\widehat{\gamma}_0+
2\sum_{k=1}^{L}\left(1-\frac{k}{L+1}\right)\widehat{\gamma}_k,\qquad
SE_{\mathrm{HAC}}(\widehat{s})=\sqrt{\widehat{\Omega}/n}.
\]

带宽选择规则在开发阶段固定，并报告相邻带宽的敏感性。零方差、非有限值、无效长期方差、严重结构变化或数据不足均返回明确状态。Sharpe 的年度显示、样本频率和标准误必须一致；序列相关存在时，简单乘以年度周期数的平方根不能代替真实长周期收益分析。

方法依据为 [Newey–West 的 HAC 估计](https://www.nber.org/papers/t0055) 与 [Lo 的 Sharpe 统计研究](https://traders.studentorg.berkeley.edu/papers/The-Statistics-of-Sharpe-Ratios.pdf)。以上影响函数接口是本规划对项目估计流程的具体设计，需要数值与模拟校准。

模拟方案、实际覆盖率和固定候选集合误报率见 [PLAN-05 离线模拟校准](PLAN_05_SIMULATION_CALIBRATION.md)。

### 6.4 多重选择与 DSR

保留 PSR、DSR 和 PBO 的独立输出，但区分：

- 单个策略 Sharpe 的抽样标准误。
- 不同候选 Sharpe 的离散程度。
- 候选间相关性和被观察的完整尝试历史。

这些量用途不同。HAC 负责时间依赖下的抽样不确定性；它不会自动补偿反复修改策略、参数和评价指标的选择偏差。[DSR 原文](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf) 将跨试验离散程度和试验数量纳入选择修正。

将 HAC 标准误放入 DSR 形式的分数，单独标注为待校准扩展，不直接继承标准 DSR 的解释。当前 PSR/DSR 的 0.95 条件继续保留；新实现须先核对定义、合成数据误报率和适用条件，再确定新版准入规则。不能通过重命名统计量或降低阈值绕过现有研究要求。

统计评价同时包含选择修正后的净优势区间、未参与选择的数据结果、成本压力、跨时期稳定性和有效信息量。PBO 的数值描述相应重采样设计中的过拟合现象，不解释为未来实盘失败概率。

### 6.5 配对区块自助法

各策略、参照方案及状态过滤版本在相同日期形成收益向量。一次抽样对所有列使用共同的区块索引，保留时间相关和候选间相关。区块长度及其候选范围在开发数据上确定，不按最显著的结果选取。

两类实验分别实施：

| 目的 | 抽样对象与做法 | 可以支持的结论 |
| --- | --- | --- |
| 已冻结策略之间的配对比较 | 同步抽取已实现收益向量 | 对该历史序列与冻结策略的条件性差异估计 |
| 评估选择过程 | 在明确零假设下构造居中序列，同步抽样并重复已登记的选择规则 | 该选择范围内的误选或最大统计量校准 |

如果过程包含重新训练特征、重估阈值或动态选模，需要在相应训练窗口重做这些步骤，或明确把结论限定于固定候选收益。仅对收益列重采样，不能替代整个学习过程的验证。平稳区块抽样的方法来源见 [Politis–Romano](https://statistics.stanford.edu/technical-reports/stationary-bootstrap)。

固定候选配对区间和联合零假设的模拟设置见 [PLAN-05 配对区块校准](PLAN_05_PAIRED_BOOTSTRAP.md)。

每次随机化重做训练、选择和样本外评估的设置见 [PLAN-05 重新训练与动态选模校准](PLAN_05_DYNAMIC_SELECTION_CALIBRATION.md)。

重采样已含成本的收益时，不在拼接边界额外创建交易。对最大回撤和恢复期，还需用连续历史窗口与前瞻运行复核；人工拼接的区块边界会改变路径。尚未恢复的回撤记录截至观察末日的持续时间下限和删失标记。

定额运行费用、月度充值和最小订单限制会随资金路径改变。仅抽样冻结收益列时，结论限定于对应历史资金情景；评估其他本金或现金流情景，需重新运行数量和费用账本。不能把比例费用条件下的收益序列直接外推为所有资金规模的 CNY 结果。

### 6.6 有效信息与研究结论

首轮建议预先规定：包含必要运行费用后的净优势，其经过选择控制的单侧 95% 区间下限大于零；同时满足选定的回撤、尾部损失和恢复要求。与买入持有的比较可以采用第 6.1 节的收益改进或防御改进目标，不能把少承担市场风险造成的收益下降隐藏起来。95% 是项目待确定的研究政策，统计方法须先校准；它不代替现行 PSR/DSR 条件。

输出采用 PASS、FAIL、INSUFFICIENT_DATA 三种结论，并说明是哪项条件决定结果。交易笔数、观察周数和正收益窗口占比只是信息量描述；不存在“达到 30 笔”或“观察 8 周”即可证明有效的统一规则。

首轮评价记录：

- 不同市场时期、共同数据覆盖和独立风险事件数量。
- 净收益、费用和暴露分布；最差窗口与参数邻域稳定性。
- 区块长度、HAC 带宽、成本、延迟、汇率和缺口情景的敏感性。
- 数据与试验历史是否完整，最终保留数据是否仍具有独立性。
- 样本不足时需要继续观察的具体信息。

没有候选满足条件时结束该轮选优，保留结果并继续观察。策略上线时间由这些条件决定，不按预定日期强行通过。

## 7. 风险维度、五态显示与动态调整

### 7.1 四类风险分别维护

| 风险维度 | 示例 | 必要动作 |
| --- | --- | --- |
| 运行安全 | 行情过期、账户不同步、订单未知、日志无法持久化、授权失效 | 停止新增风险；按已知状态查询、对账、撤销增加风险的挂单或等待恢复 |
| 所有者风险预算 | 净值回撤、CNY 损失金额、账户暴露超限 | 按生效配置减仓或暂停；达到人工恢复条件后保持暂停 |
| 市场状态 | 波动率升高、趋势效率下降、流动性恶化 | 仅执行已通过实验的仓位限制 |
| 资产与交易场所事件 | 提现异常、下架安排、兑换价格异常 | 启用对应事件规则、核实来源并限制受影响资产 |

NORMAL、STRESS、CRISIS、UNKNOWN、RECOVERY 可作为状态显示及市场策略接口。底层分别保存各维度原因、开始时间、解除条件和恢复权限；单一枚举不承担全部事实。

UNKNOWN 由关键数据不足或订单状态不明触发，不能通过“市场已经平静”解除。CRISIS 后可以进入 RECOVERY，但仍需同时满足账户、订单、数据、授权和持久化条件。

### 7.2 风险下降与恢复

风险收紧立即进入处理流程，不受普通状态驻留时间或换仓成本等待限制。风险恢复采用较慢的条件：持续健康、完成对账、没有遗留未知订单、预算仍可用、授权有效，以及必要的人工确认。

停止新增风险与卖出现有资产是两项独立动作。现货退出需要可确认的可卖数量、待成交卖单、手续费余量和价格条件；Spot 的减风险语义由本地检查实现。出现未知订单时，先核实其可能造成的最大持仓，再生成新的退出订单。

存储故障可能同时阻止新增订单和安全地记录退出订单。应预留风险处理容量并设人工处理程序，不承诺任何故障下都能立即清空持仓。

风险阈值分为两组：30% 与 50% 的研究情景，以及唯一生效的实盘配置。研究情景中出现的预警、减仓和停止比例均不自动取得实盘权限。充值、授权续期和进程重启不能解除已经触发的账户风险暂停。

### 7.3 市场过滤器的实验顺序

先完成以下增量实验，所有版本共用相同的运行安全限制：

| 实验 | 内容 | 需要回答的问题 |
| --- | --- | --- |
| A0 | 固定配置比例的已冻结策略 | 原始策略是否具有净优势 |
| A1 | A0 加波动率目标或波动率上限 | 是否改善收益与风险的组合 |
| A2 | A1 加 STRESS/CRISIS 仓位限制 | 是否优于更低的固定配置比例 |
| A3 | A2 加趋势效率指标 ER | 是否提供独立增益 |
| A4 | A3 加恢复持续时间与状态迟滞 | 是否减少反复交易而保留风险改善 |
| A5 | 增加相关性、资金费率或外部信息 | 新数据与复杂度是否值得承担 |

逐项实验之后做必要的删除单项实验，检查交互作用。固定低仓位对照的参数只在训练阶段确定，不能利用测试期平均暴露反推最有利的对照。

ER 低只表示指定窗口内方向效率低，不直接推出均值回归可盈利；高相关性不直接预示下跌。资金费率属于衍生品信息，只有逐时点可得且在现货策略上有增量价值时才采用。

分位数阈值和波动参考分布按固定日程更新。危机期间使用明确的参考版本和解除规则，避免持续高波动被新窗口吸收后自动恢复为正常。报告中的具体分位数、倍数、驻留小时数均作为待测试参数。

### 7.4 自动适应的范围

自动运行允许按已验证规则更新仓位、读取当前波动率和切换已批准状态。模型更换、扩大品种范围、提高风险限额及引入新数据源进入离线研究和新的版本批准。

日常监控分开处理故障报警与策略表现评价。故障随事件处理；策略表现按预先固定的观察窗口评价，避免每天反复检验后把偶然显著当作改变规则的理由。新闻、社交内容和大模型建议先进入只读研究记录，不直接改变订单和权限。


## 8. 执行核心与持久化

### 8.1 继续使用当前订单流程

当前实现的核心顺序保持为：

    Intent 持久确认
      → 订单确认与资源预留
      → Prepared 持久确认
      → 最终条件复查与一次性 claim
      → 调用提交端口
      → 结果事件持久确认
      → 更新订单状态
      → 在满足条件时释放资源

Intent 与 Prepared 各自有用途；未来批量持久化仍需保留两者的先后和确认语义。订单 WAL 与控制状态日志是不同组件，设计异步化时分别说明其所有者、记录类型、恢复顺序和相互依赖。

E0 实盘账务接入后，以已经持久化的规范成交事件驱动账务投影，并验证其重复处理与恢复行为。

三项不变条件：

1. 可能已发送的订单保持占用相应资源，直到取得可接受的终局结果或其他明确关闭结果。
2. Prepared 写入失败或超时，仍可能已经写入存储；不能据此释放槽位或归类为未发送。
3. 成交与终态事件先完成持久确认，再更新权威投影并释放资源。

Binance 官方说明，超时和部分服务器错误可能对应未知执行结果，应通过私有流和查询确认。恢复逻辑必须保留这种不确定性。[Binance REST API 说明](https://developers.binance.com/en/docs/products/spot/rest-api)

### 8.2 未发送、未知与重复事件

- 仅 Intent 的订单按现有孤儿规则恢复，不直接重发。
- Prepared/Submitting 后没有结果的订单恢复为 Ambiguous，查询与对账。
- OrderNeverSent 只用于明确没有产生提交效果的情形，并先完成关闭事件的持久确认。
- claim 已经成功后，后续中断不能仅凭本地缺少响应认定未发送。
- 同一业务意图的未知提交禁止盲目重试；一次查询未发现订单也不能自动证明订单从未存在。

数量、成交金额、手续费和订单状态分别去重。仅用累计成交数量的最大值计算差分，不能覆盖数量不变的手续费补报或晚到成交金额修正。成交身份、累计字段和更正事件共同管理，已结束订单需保留适当识别信息，防止迟到消息影响新订单槽位。

### 8.3 异步 WAL 的启动条件

先完成 FI-046 的目标主机测量：各次持久追加的延迟分布、最慢窗口、日志压力、系统并发、私有流积压、撤单与恢复时效。

若同步流程能满足已选策略与故障响应要求，继续使用当前架构。若阻塞已经影响安全处理或可接受延迟，再启动 PERF-01：

- 单一订单状态所有者只管理订单与资源状态。
- WAL 工作线程接收有界请求并返回有界完成消息。
- 请求身份包括订单、运行代、槽位代、记录阶段和必要的授权版本；完成消息还携带对应持久序号。
- 状态机显式等待 Intent ACK 和 Prepared ACK，等待期间继续处理撤销、过期、私有流与故障。
- Prepared ACK 后重新读取所有动态条件，完成同一提交权限协议下的 claim，再由真实发送者执行提交。
- 满队列、迟到 ACK、线程重启、关闭过程与持久结果不明分别有状态转换。旧完成消息不得推进当前运行代；其已经持久化的订单事实仍需按恢复规则处理。
- 超时只改变等待和报警状态，不将可能已经写入的记录变成“没有写入”。

当前 SubmitReadyToken 不包含 WAL 序号；当前同步调用顺序提供了先持久确认再 claim 的约束。异步实现必须增加明确的请求与完成身份，不能仅把同步 fsync 移到后台后继续沿用原先的函数调用假设。

Linux fsync 完成文件数据和相应元数据同步；新增或替换文件还须考虑目录项持久化。磁盘短写、EIO、ENOSPC 和目录同步失败均进入故障测试。[Linux fsync 文档](https://man7.org/linux/man-pages/man2/fsync.2.html)

### 8.4 故障模型分别验证

| 故障类别 | 要验证的结果 |
| --- | --- |
| 本地拒绝 | 无外部提交效果时完成持久关闭，恢复后不重复处理 |
| 提交前后进程终止 | 每个边界恢复后能够区分孤儿、未发送和未知 |
| 请求成功但响应丢失 | 保持未知并对账，不生成第二个业务订单 |
| 重复、乱序、晚到成交 | 数量、费用和风险占用保持一致 |
| 日志线程阻塞或完成队列满 | 新增风险受控，查询与报警行为符合明确设计 |
| 操作系统或虚拟机故障 | 在该环境的存储保证下恢复；与单进程终止测试分别报告 |
| 主机完整旧快照恢复 | 按授权恢复策略处理，不自动沿用旧运行权限 |

本地日志和交易所之间不建立跨系统原子事务。系统目标是约束提交次数、保存未知状态并完成幂等核算；业务结果由交易所记录和恢复过程共同确定。

## 9. 硬件范围批准与主机安全

### 9.1 自动交易采用范围批准

延续 R-25：Owner 用已有硬件密钥批准一段有期限、有限额的交易范围，执行进程在该范围内自动处理订单。范围批准实现和验证完成前，保留现有逐单 OrderConfirmation。

最小范围内容包括：

| 类别 | 必须表达的内容 |
| --- | --- |
| 身份 | 环境、账户、部署或存储身份、Owner 密钥身份、格式版本 |
| 版本 | 范围序号、策略版本、政策版本、运行激活身份 |
| 能力 | 品种、方向、订单类型、允许的策略动作 |
| 限额 | 单笔金额、累计授权额度、账户暴露、价格偏离、必要的次数限制 |
| 时间 | 绝对开始与到期时间、执行端允许的最长有效期 |
| 防重用 | 当前批准请求、作用域和安装状态之间的绑定 |
| 恢复 | 新增风险权限、处理既有仓位的权限及人工恢复条件 |

字段使用明确的单位、整数范围和唯一编码，拒绝重复字段、未知关键字段与不支持的版本。可读批准界面从最终签署对象直接生成。

先验证现有 YubiKey 可用的接口，再选择一条实现路线。WebAuthn、OpenSSH 安全密钥签署和其他硬件接口具有不同的调用和验证规则，不同时实现多个方案。采用 WebAuthn 时必须验证完整认证仪式及请求绑定；用户存在与用户验证的含义按规范处理。[W3C WebAuthn](https://www.w3.org/TR/webauthn-3/)

硬件触摸或 PIN 不能替代对交易内容的可信显示。初期明确签署终端属于信任范围；若要抵御该终端被控制，应使用独立设备取得并显示完整批准内容，再由 Owner 确认。普通安全密钥本身不提供完整交易参数显示。

### 9.2 提交、撤销与预算

当前 SubmitAuthority 已将提交 claim 与撤销放在同一原子 epoch 上竞争。范围的安装、替换和撤销应接入这一协议；先单独读取范围状态、再进行不关联的 claim，不能保证两者一致。

预算分两层：

- 每份范围的授权额度：遵循现有设计，在 Prepared 持久记录中形成扣记；明确未发送并完成持久关闭后，按规则归还。
- 账户整体限制：覆盖所有范围下的持仓、在途风险和已触发的损失暂停。若增加日历期间或滚动成交预算，使用单独账户状态并明确时间规则。

Owner 签署新范围可以授予新的范围额度；账户风险暂停、既有持仓和未知订单不会因此消失。账户期间预算若启用，续签也不会将其重置。该新增预算政策需与现有范围额度分别实现和测试。

撤销对外报告三个阶段：请求已接收、对后续 claim 已生效、撤销结果已持久化。已先行成功 claim 的订单继续按可能在途处理，查询并核算；撤销响应不声称这些订单已经消失。

有效期采用保守的时间上界和已验证的时钟状态。普通 Linux 调度下，检查完成到网络实际发送之间仍可能发生抢占；响应时间指标通过测量和故障模型定义，不承诺绝对的硬实时截止。

### 9.3 到期后处理既有仓位

新增风险授权到期后停止买入或扩大暴露，既有仓位继续进入已批准的风险处理流程。

处理既有仓位的权限单独定义：只允许针对已登记资产、已知可卖数量和已核实在途订单减少风险；继续受价格、交易规则、持久化和账户检查约束。其生命周期覆盖该批仓位的处理完成，无法安全判断时进入人工恢复。

因此，数小时的新增风险授权可以与数周的持仓策略配合。需要明确到期后哪些正常策略退出仍可自动执行、哪些需要续签，以及续签失败时如何通知。不能在授权过期后留下完全没有退出权限的持仓。

### 9.4 重启、旧副本与接管

首轮采用低复杂度恢复方式：执行进程冷启动后完成日志恢复与交易所对账，新的风险增加能力需重新激活并由 Owner 确认。正常运行中的自动交易不因此变成逐单审批。

新的激活身份与本机数据绑定能够约束正常重启流程。对于包括内存、时钟和磁盘的完整虚拟机旧快照，需独立信任域保存最新授权状态，才能提供更强的旧状态拒绝能力；随虚拟机一起恢复的本地记录不能承担这一作用。外部单调状态服务列为后续按风险选择的能力。

首轮只安排单执行主机与人工恢复。备用主机接管之前，必须确认旧主机已经停止交易能力，通过停机、网络限制或交易所凭据撤销等适用方式完成，再恢复账户和订单。只有共享存储租约或主机心跳不足以阻止旧进程继续调用交易所。

### 9.5 权限边界与外部内容

执行核心、研究程序、通知程序和未来的管理界面使用独立权限。研究与通知不持有交易凭据；交易凭据仅授予必要交易能力，关闭提款能力并按实际账户功能限制来源地址。

范围批准约束遵循该程序的操作。能够直接取得交易 API 凭据并绕过程序的攻击者，需要由凭据隔离和交易所权限限制处理；需要更强保护时，将凭据与策略进程分离到独立的受限签署服务。操作系统最高权限控制仍属于独立威胁范围。

外部新闻、网页和 AI 输出只允许成为经过解析的研究输入；不获得本地命令、审批、配置修改或订单权限。对来源独立性、发布时间和修订进行检查，多家转载同一消息只计同一个信息来源。

远程写入管理仍按 R-24 延后。未来有网页需求时再评估 Cloudflare Access、Tunnel 和 Turnstile；这类入口防护不进入订单循环，也不替代硬件批准。图片验证码、滑块和拼图不作为自动执行核心的身份判断方式。

## 10. 4C8G 部署与通知

### 10.1 以目标负载决定 CPU 和内存安排

4 核 8 GB 是部署目标，CPU 编号分工是待测配置。先测量行情接收、私有流、对账、订单处理、持久化和通知各自的资源需求，再为订单线程保留独立核心，并避免日志和管理任务争用该核心。

热路径继续遵循仓库的固定容量、零动态分配和并发规则。通知、压缩、模型训练、报告生成和非必要文件工作放在订单处理之外。本地研究产生的候选策略通过后，再转入受限的执行配置。

目标主机验证至少包括：

- 实际品种数下的正常负载、行情突发、重连补数据和同时对账。
- CPU 占用、调度等待、内存峰值、缺页、磁盘剩余空间和队列最高占用。
- 私有流处理时效、行情新鲜度、每个持久化阶段耗时和最终授权有效性。
- 日志写满、通知故障、备份运行和系统维护同时发生时的表现。
- 依据实测负载保留的容量余量；阈值在正式测量前确定并记录。

若采用专享 vCPU，仍需验证磁盘和网络条件。CPU 专享本身不确定持久化延迟和交易所连接质量。

### 10.2 最小运行能力

| 能力 | 首次自动实盘前的完成条件 |
| --- | --- |
| 进程启动与停止 | 无有效激活权限时不能新增风险；异常退出后恢复到受限状态 |
| 日志与容量 | 有界保留、空间预警、满盘处置和可用恢复副本 |
| 状态可见性 | 能看到账户、在途订单、授权、数据新鲜度、故障原因和最后成功对账时间 |
| 时间管理 | 时钟偏差与不确定度受检查；异常时按政策停止新增风险 |
| 主机权限 | 执行服务身份、文件权限、网络访问和必要的系统隔离已验证 |
| 人工恢复 | Owner 能从干净状态完成查询、核对、受限恢复和凭据撤销 |

最小通知采用飞书与 Telegram。通知内容只包含处理故障所需的事件、时间和状态，不包含凭据或批准材料。推送服务接收成功、平台送达和 Owner 已阅读分别记录；收到通知不自动扩大交易权限。

还需有能够发现执行主机整体失联的外部健康检查。若主要与备用通知都依赖同一个已故障 VPS，无法承担主机整体失联报警。独立健康检查可以使用适合预算的已有设备或服务，其可用性与费用纳入测试。

短信和语音以后按实际产品用途、个人账号资格、目标地区、模板、送达状态和费用单独核实。具体升级秒数按故障严重程度和 Owner 可响应时间确定，不直接采用研究报告中的示例数值。

## 11. 研究与实盘的一致性

以规范数据记录、策略参数、订单意图和账务事件作为共用输入输出。优先复用已有可用组件，避免为了首轮简单策略全面重写研究框架。

回放测试逐步比较：

1. 同一时刻可见的数据和窗口初始化状态。
2. 特征值、信号、持仓目标和退出原因。
3. 价格、数量、费用、订单状态与剩余可用资产。
4. 重启后继续运行与不中断运行的对应结果。

价格、数量、费用最小单位、订单身份和状态转换要求精确一致。浮点特征采用明确误差范围，同时检查阈值附近是否出现不同交易决定。若设计中增加阈值缓冲区，应作为策略规则重新研究，不能只在实盘端添加。

历史模拟、实时纸面交易、Testnet 与真实资金阶段分别回答不同问题。Testnet 可用于验证协议和恢复，不用于估计生产市场的实际滑点。实盘影子观察可以测量真实数据与可成交价格；实际资金订单仍需完成明确的授权和阶段条件。

### 12.3 每轮实验的结束规则

每轮开始前确定候选集合、主要指标、观察窗口和费用情景。完成后只选择一个明确结果：

- 继续：候选满足要求，进入下一阶段。
- 补充信息：记录缺少的数据或独立观察，停止重复调参。
- 创建新版本：提出具体新假设，登记新的试验范围。
- 停止：不再为该候选投入部署或数据费用。

不将所有失败都转化为增加模型、指标或外部服务的理由。

## 14. 关键验证场景

### 14.1 研究与资金

| 场景 | 预期结果 |
| --- | --- |
| 下跌后充值 | 单位净值与历史回撤不因充值改善，累计资金正确增加 |
| 平台内外支付同一费用 | 综合结果相同，每笔费用只扣一次 |
| 买入手续费收基础资产 | 卖出数量使用实际到账数量 |
| 小额资产不足最小订单 | 保留并标记余额，不产生虚构成交 |
| 手续费迟到、重复成交与修正事件 | 数量、金额和费用分别正确处理 |
| USD/CNY 变化且币价不变 | CNY 账正确显示汇率贡献 |
| 引入未来值或修订信息 | 逐时点检查拒绝，合法历史策略正常运行 |
| 无优势、相关和厚尾合成收益 | 统计程序的拒绝率与区间覆盖按预先方案校准 |
| 共同区块比较 | 所有候选使用相同抽样索引，保留配对关系 |
| 保留数据被再次用于设计 | 访问被登记，后续结论按新的选择历史评价 |
| 市场过滤降低暴露 | 同时比较训练期确定的低固定仓位，报告风险和收益代价 |
| 尚未恢复的回撤 | 保留持续时间下限，不记作已经恢复 |

### 14.2 执行、授权与运行

| 场景 | 预期结果 |
| --- | --- |
| Intent、Prepared、提交和结果之间逐点终止 | 恢复状态正确，未知订单不盲目重发 |
| Prepared 超时后迟到成功 | 保持订单身份与资源占用，不重复提交 |
| claim 与撤销并发 | 撤销先发生时拒绝；claim 先发生时保留可能在途状态 |
| 多订单同时申请预算 | 合计预留与已用额度不超过规则 |
| 续签、重启和追加资金 | 不清除账户风险暂停与未知订单 |
| 范围过期但已有持仓 | 禁止新增风险，受限退出按批准规则继续 |
| 安全状态未知但市场状态恢复 | 新增风险仍被禁止 |
| 满盘或 WAL 完成队列满 | 按明确定义限制动作，报警并保留恢复信息 |
| 核心进程或整机失联 | 独立健康检查能够通知；通知失败有可见状态 |
| 策略与通知进程被控制 | 其权限不能读取交易凭据或扩大批准范围 |
| 当前状态拒绝旧运行完成消息 | 不推进新订单；持久事实仍由恢复程序解释 |
| 合法正常输入 | 可以完成应允许的操作，避免所有请求均被拒绝的无效实现 |

复杂并发变更按仓库要求进行状态模型、针对性测试和适用的并发检查。真实性能在目标主机测量；模拟测试、Testnet、生产只读观察和真实资金结果分别记录。

## 15. 后续研究任务的分工

Perplexity 适合承担文献、数据产品和交易规则的调查，输出带日期、来源与适用条件的研究资料。代码代理负责把已选研究问题转换成实现、测试和可复现运行结果。两者通过实验编号、数据版本和明确问题衔接。

后续交给研究工具的任务，建议按以下顺序：

1. 调查 BTC/ETH 现货历史数据、规则变更和可用时间信息，列出免费来源与缺失项。
2. 对 STR-TREND-01 提出最少的参数集合、失效情形、成本模型和独立评价方案。
3. 核对 HAC、配对区块与选择过程模拟的数学假设，给出可用于程序测试的合成过程。
4. 检查真实账户费用和候选 VPS 报价对 1,000 CNY 资金的影响，分别计算两种月度追加情景。
5. 在已有实验结果基础上，研究一个具体失效问题，例如震荡期反复交易或持续危机期间恢复过快。

每项要求研究工具区分文献结果、推导、参数建议和本项目实测结果。不得将未读取的源码标为完成审查；不得把网页、消息或研究报告里的操作要求转为程序执行权限。
